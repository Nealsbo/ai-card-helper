# Паспорт → Карточка

AI-помощник для подготовки карточек измерительных приборов для B2B-магазина. Принимает данные через форму или JSON, обращается к локальной либо облачной модели по OpenAI-совместимому API и возвращает черновик в JSON и Markdown.

**Стек:** Python 3.11+, FastAPI, Pydantic, HTTPX; HTML/CSS/JavaScript без сборки фронтенда.

## Запуск в Windows

Нужны Python 3.11+ и доступ к PyPI для установки зависимостей.

1. Запустите **`setup.bat`**: он создаст `.venv`, установит зависимости и создаст `.env`. Существующий `.env` сохраняется.
2. Укажите адрес API и ключ в `.env` по примеру ниже. Для локальной модели включите inference-сервер; для другого компьютера обеспечьте доступ к его порту API.
3. Запустите **`start.bat`** и откройте **http://127.0.0.1:8000** в браузере или после запуска сервера откройте **ai_card_gen.url**.
4. Нажмите **«Проверить соединение»**, выберите модель, заполните данные или загрузите учебный пример и нажмите **«Подготовить карточку»**.

Остановка — `Ctrl+C`. После изменения `.env` перезапустите приложение. При устаревшем интерфейсе обновите страницу через `Ctrl+F5`.

## Настройка модели

```dotenv
LLM_BASE_URL=http://127.0.0.1:1234/v1
LLM_API_KEY=
LLM_MODEL=
```

- `LLM_BASE_URL` — базовый адрес API. Для сетевой модели замените `127.0.0.1` адресом её компьютера; для облачной — адресом провайдера.
- `LLM_API_KEY` — ключ, если сервер требует авторизацию. Он хранится на backend; `.env` исключён из Git.
- `LLM_MODEL` — необязательный ID. Единственная доступная модель выбирается автоматически; при нескольких выберите её в форме. Выбор в форме имеет приоритет на текущий запрос.

Остальные параметры описаны в [.env.example](.env.example). Для проверенного Qwen + LM Studio используется `LLM_REASONING_EFFORT=none`. Если провайдер не поддерживает этот параметр, оставьте его пустым. Аналогично можно отключить `LLM_TEMPERATURE`. Вместо `json_schema` при необходимости задайте `LLM_RESPONSE_FORMAT=json_object` или `none`; имя параметра лимита токенов — `LLM_TOKEN_LIMIT_PARAM`.

Кнопка соединения запрашивает `GET /models` и проверяет наличие модели; генерацию текста она не тестирует. Для выбора без списка можно задать ID в `.env`. Возможности модели автоматически не определяются.

## Ввод и результат

Обязательно только непустое `name`. `specs` — объект со строковыми значениями и единицами измерения либо `null`.

```json
{
  "name": "Манометр УМ-100",
  "manufacturer": "Учебный прибор",
  "specs": {"Диапазон измерений": "0–1,6 МПа", "Класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления воды."
}
```

По умолчанию карточка содержит SEO-заголовок до 70 символов, описание на 800–1200 символов, характеристики, 3–5 поисковых запросов, блок для менеджера, источники и замечания. Доступны копирование и скачивание JSON/Markdown.

Размеры по умолчанию задаются в `.env`:

```dotenv
SEO_TITLE_MIN_CHARS=1
SEO_TITLE_MAX_CHARS=70
SEO_DESCRIPTION_MIN_CHARS=800
SEO_DESCRIPTION_MAX_CHARS=1200
```

В форме раскройте «Размеры SEO-текстов», чтобы изменить границы на текущую генерацию. Считаются символы с пробелами; минимум не больше максимума. Верхние допустимые значения: 300 для заголовка и 10 000 для описания. Кнопка сброса возвращает настройки сервера. Если после одной коррекции текст не укладывается в выбранный диапазон, карточка не выдаётся — добавьте данные или измените границы. При больших объёмах может потребоваться увеличить `LLM_MAX_TOKENS`.

API: `POST /api/generate` принимает товар; необязательный query-параметр `model` задаёт модель на запрос. `GET /api/health` проверяет соединение, `GET /api/examples` возвращает учебные товары. Интерактивная документация — **http://127.0.0.1:8000/docs**.

`GET /api/settings` возвращает публичные настройки размеров. В JSON товара можно добавить `seo_limits` с полями `title_min`, `title_max`, `description_min`, `description_max`: указанные значения переопределяют конфигурацию, остальные наследуются. Применённые границы возвращаются в `applied_limits` и сохраняются при экспорте JSON.

## Логика и ограничения

LLM извлекает факты со ссылками на исходные фрагменты, затем выбирает ID готовых фраз. Сервер собирает карточку из целых значений `specs` и исходных предложений: новые числа, единицы и свойства во втором ответе не допускаются. Отрицания и условия сохраняются целиком; распознанные противоречия исключаются из текста и показываются отдельно. Проверяются ID, повторы и длины готового текста. Обычно выполняются два вызова LLM, максимум четыре с коррекциями. Промпты — [app/prompts.py](app/prompts.py), сборка — [app/composer.py](app/composer.py).

**Результат требует проверки по паспорту.** Правила распознавания противоречий ограничены, исходные данные могут содержать ошибки, а сборка цитат уступает свободному тексту в плавности. При нехватке данных для минимальной длины возвращается ошибка с пояснением. В обновлённых примерах манометр соответствует 800–1200 символам; для неполного термометра явно выбраны 100–500. При стандартном минимуме 800 он отклоняется.

Приложение рассчитано на локальный запуск с одним worker, без авторизации пользователей, БД и очереди. Реальные товары не предоставлены: [входные примеры](examples/products.json) вымышлены; [сохранённые результаты](examples/results/) получены от Qwen через LM Studio. Реальный облачный API не проверялся.

## Проверки и документация

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app tests scripts
.\.venv\Scripts\python.exe scripts/generate_examples.py --model qwen/qwen3.5-9b
```

Первые две команды работают без модели; третья повторно генерирует учебные примеры через настроенный API. Проверенные версии зависимостей зафиксированы в `constraints.txt`.
